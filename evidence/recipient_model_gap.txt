## Local Granite feasibility probe

Ran Granite 3.0 1B A400M Q2_K in the prebuilt s390x image with one CPU thread and a synthetic request about the same recipient label. Generation took 83.8 seconds and returned malformed prose instead of the requested JSON classification. The earlier Q4_K_M case-note probe timed out at 90 seconds; the 50-case note evaluation accepted 0/50. Current service configuration does not run the LLM during `/score`; Granite is an optional asynchronous case-note path for HIGH/CRITICAL results.

## Interpretation

The scoring model does not consume `payee_name`; it scores transaction and interaction features. The optional Granite path is too slow and unreliable in these checks to drive an immediate transfer decision. No recipient-specific rule or artificial model score was added. The customer UI now describes LOW as “no strong pressure signals found,” says recipient ownership is not verified, and asks for an explicit “Confirm transfer.” A capable, tested local semantic model or an approved low-latency LLM integration is needed before recipient-name review can safely participate in the decision.
